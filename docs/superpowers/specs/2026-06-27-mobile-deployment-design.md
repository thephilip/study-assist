# Mobile Deployment — study-assist

**Date:** 2026-06-27
**Status:** Approved
**Goal:** Test whether a paid Android app generates income. iOS only after validation.

## Strategy

The free PWA is already installable on any device. A paid WebView wrapper of the same app is
not a technical challenge — it's a business hypothesis. Test it for $25 (Play Store account)
before spending $99/year (Apple) + iOS implementation time.

**Decision path:**
- Android via Capacitor → paid download, no IAP ($25, a weekend)
- If Android revenue covers the Apple tax within 3 months → add iOS
- If Android flops → total loss is $25 and a weekend. No iOS work, no Flutter rewrite.
- ponytail: Flutter native rewrite is a separate spec. Deferred until Android+iOS revenue
  collectively justifies a full-time build.

## Architecture

```
study-assist/
├── src/                          # One 3-line change: paid-build flag in entitlements.ts
├── vite.config.ts                # GH Pages config (unchanged)
├── vite.config.native.ts         # New: base: '' for local assets
├── capacitor.config.ts           # New: app ID, name
├── android/                      # Generated by npx cap add android (gitignored)
└── ios/                          # Generated later (gitignored)
```

Chosen over Bubblewrap (TWA) because an image-processing app needs bundled assets for full
offline UX — a URL wrapper feels broken when the spinner shows on first launch.
ponytail: Capacitor is a heavier dependency than Bubblewrap, but the bundled-asset UX
difference justifies it for this app type.

## Capacitor Setup

```bash
pnpm add -D @capacitor/core @capacitor/cli @capacitor/android
npx cap init study-assist com.studyassist.app
npx cap add android
```

A single config override: `base: ''` in a separate Vite config so the GH Pages deployment
(`base: '/study-assist/'`) and the native build stay independent.

Build script: `"build:native": "vite build --config vite.config.native.ts && npx cap copy"`

Hot reload on device: `npx cap run android --livereload`

## Monetization

**Paid download only.** No IAP, no subscriptions, no trials. The app store refund window
(GPlay: 2 hours, App Store: 14 days) is the demo period.

The web PWA remains free with its existing brand-pack gating. The paid app ships with
`VITE_PAID_BUILD=true` — `entitlements.ts` checks this env var and skips the gating check
(writes the unlock flag on first launch). One three-line change in the codebase, the rest
unchanged.

ponytail: If paid downloads don't cover the $25 Play fee, this entire experiment cost
less than dinner out. Don't overthink it.

## App Store Assets

- **Privacy policy:** "All image processing is performed entirely on-device. No images or
  data are uploaded, stored, or transmitted." Paste this into the Play Console field.
- **App icon:** Resize existing `public/icons/` with ImageMagick one-liner.
- **Screenshots:** Chrome DevTools → Pixel tablet emulation → 4 screenshots.
- **Category:** Art & Design.

## Release (Android)

1. `pnpm build:native`
2. Android Studio → Build → Generate Signed Bundle
3. Google Play Console → Internal testing → Production

**Prerequisites:**
- Google Play Developer account ($25, one-time)
- Keystore (backed up externally)

## Release (iOS — conditional)

Only if Android revenue >= $99/year within 3 months of launch:

1. Get the Mac
2. `pnpm add -D @capacitor/ios && npx cap add ios`
3. Xcode → Archive → App Store Connect

## What's not happening

| Thing | Why skipped |
|---|---|
| IAP plugins | Paid download covers it. Add IAP if the fixed price doesn't convert. |
| Flutter rewrite | Revenue-dependent. Separate spec. |
| iOS on day one | No Mac. Test with Android first. |
| CI/CD automation | 8th release problem, not the 1st. |
| Receipt validation | Play Store handles purchase verification. |

## Success Criteria

Ship Android. If it generates any net positive revenue within 3 months, the model works.
If it doesn't, the PWA still exists and nothing is lost.
